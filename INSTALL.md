# Battery Monitor Rings 11 — Installation

## Normal users (portable binary)
Extract the **entire** `LGSTrayEx-Rings-Portable-x64.zip` and launch `LGSTray.exe`.
Windows 11 x64 is required. The self-contained publication includes the .NET desktop runtime and HID worker. No SDK, Windhawk, MSI or other setup application is required. The root contains only LGSTray.exe and the app folder. Keep both together. The launcher uses the .NET Framework included in Windows 11; the actual UI and HID worker remain self-contained .NET 10. The portable binary is generated by the build; it is **not** contained in this source archive.

## Developers (source archive)
Exit the running old version, extract this archive, double-click `BUILD-RINGS.cmd`. It uses an existing .NET 10 x64 SDK, or installs the SDK in `.sdk-x64` when missing. Network access is required to retrieve missing SDK/NuGet packages. The script publishes both executables and opens `bin/Release/Publish/win-x64/Standalone`. The distributable ZIP is `bin/LGSTrayEx-Rings-Portable-x64.zip`. To run regression tests first, use `BUILD-RINGS.cmd -Test`. GitHub Actions uses the same PowerShell implementation.

Settings remain in the existing local application data directory. The right-side strip uses a verified free gap next to the notification area. If upgrading from a version with an Explorer layout provider, exit it and restart Explorer once (or sign out), then extract this archive into a new folder. Keep the old folder only if needed for rollback.

## Device identity limits
Exact matching serials and confirmed physical identifiers can be merged automatically. Unambiguous Logitech HID / G HUB mode-family sources may also be grouped reversibly without a source-count cap, including remembered offline sources, without saving an inferred physical identity. Manual separation overrides model matching. Some providers expose only a model name or temporary slot; the existing G HUB model fallback and native name-hash fallback may be ambiguous. Use manual merge/separate when necessary. Do not treat these fallback IDs as proof that two devices are the same.

## Verification
Source/static checks only in the development environment. Windows compilation, standalone launch on a machine without .NET, actual taskbar geometry and hardware detection still require Windows tests. The source archive is not a tested portable build.

## Version updates

The About page checks formal GitHub Releases tagged `rings-X.Y.Z`. It requires the expected ZIP asset and SHA-256 digest. Verified packages are extracted to a new local version directory; the original executable folder is preserved. The user explicitly confirms restart or rollback. Personalization and device inventory continue to use the existing per-user directory; the portable TOML file now lives at app/appsettings.toml. A custom TOML file is not automatically copied into a new release. Re-enable startup from the intended version if the Windows startup path still points to an older folder.

No stable release tag should be created until all automated tests and the interactive taskbar acceptance matrix pass. GitHub-hosted build runners validate compilation, not interactive shell placement.

## Portable layout (11.0.2 and later)

Launch the outer LGSTray.exe, not the worker. All support binaries and license documents are under app/; no PDB debug symbols are shipped in the user ZIP. A launch from a different working directory is exercised in Windows CI. Older versions that require a flat update archive need a one-time manual ZIP upgrade. Existing settings remain under %LOCALAPPDATA%\\LGSTray. If you enabled startup in an older installation, toggle it off/on once from the new version to register its outer launcher.

## Rings 12 maintenance

Settings, device inventory and themes are saved by a coalescing background writer. Diagnostics can be viewed and copied manually in Settings → Diagnostics. Supported update transactions use a startup confirmation from the new UI process; on failed startup the launcher attempts to restart the previous version. Local TOML overrides are copied and the old main TOML is saved as app/appsettings.previous.toml for review. Old-version cleanup is user-confirmed and restricted to marked managed folders older than seven days, preserving current and previous installations. A real release-to-release test is still required.
