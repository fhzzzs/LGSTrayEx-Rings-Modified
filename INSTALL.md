# Battery Monitor Rings.9 — Installation

## Normal users (portable binary)
Extract the **entire** `LGSTrayEx-Rings-Portable-x64.zip` and launch `LGSTray.exe`.
Windows 11 x64 is required. The self-contained publication includes the .NET desktop runtime and HID worker. No SDK, Windhawk, MSI or other setup application is required. Keep companion files next to the executable. The portable binary is generated by the build; it is **not** contained in this source archive.

## Developers (source archive)
Exit the running old version, extract this archive, double-click `BUILD-RINGS.cmd`. It uses an existing .NET 10 x64 SDK, or installs the SDK in `.sdk-x64` when missing. Network access is required to retrieve missing SDK/NuGet packages. The script publishes both executables and opens `bin/Release/Publish/win-x64/Standalone`. The distributable ZIP is `bin/LGSTrayEx-Rings-Portable-x64.zip`. To run regression tests first, use `BUILD-RINGS.cmd -Test`. GitHub Actions uses the same PowerShell implementation.

Settings remain in the existing local application data directory. The build also detects MSVC x64 and Windows SDK C++/WinRT headers, and offers to install missing C++ build tools via winget. This is a source-build dependency only. The portable archive includes NativeLayout.dll; it uses the Windows XAML Diagnostics interface to load a narrowly scoped provider in Explorer when Left is selected. Actual native occupancy is experimental and must pass geometry validation; if rejected or incompatible, safe right placement is used. See NativeLayout/README.md in the source tree. Restart Explorer to unload a staged native DLL before testing a different provider version.

## Device identity limits
Exact matching serials and already-confirmed physical identifiers can be merged automatically. Some providers expose only a model name or temporary slot; the existing G HUB model fallback and native name-hash fallback may be ambiguous. Use manual merge/separate when necessary. Do not treat these fallback IDs as proof that two devices are the same.

## Verification
Source/static checks only in the development environment. Windows compilation (including the C++ DLL), standalone launch on a machine without .NET, actual taskbar geometry and hardware detection still require Windows tests. The source archive is not a tested portable build.
